# DreamCoder (2021)

Benchmark domains from **DreamCoder: Growing generalizable, interpretable
knowledge with wake-sleep Bayesian program learning**, Ellis, Wong, Nye,
Sablé-Meyer, Cary, Morales, Hewitt, Solar-Lezama and Tenenbaum
([arXiv:2006.08381](https://arxiv.org/abs/2006.08381); *Phil. Trans. R. Soc. A*
381, 2023). Ported from the reference implementation at
<https://github.com/ellisk42/ec>.

DreamCoder is a program-induction system that grows its own DSL: starting from
a small set of primitives it alternately searches for programs that solve
tasks and abstracts the shared fragments of those programs into new library
routines. The *benchmarks* — the task sets it is evaluated on, and the initial
primitives it starts from — are what this directory ports.

## Sub-benchmarks

| Module | Tasks | Specification | Source in `ec` |
|:---|---:|:---|:---|
| `List_2021` | 217 | 15 input/output examples over lists of integers | `data/list_tasks.json` |
| `Text_2021` | 128 | 4 input/output examples over strings | `dreamcoder/domains/text/makeTextTasks.py` |
| `LOGO_2021` | 160 | one target picture, as a 28×28 bitmap | `dreamcoder/domains/logo/makeLogoTasks.py` |
| `Tower_2021` | 113 | one target tower of blocks | `dreamcoder/domains/tower/makeTowerTasks.py` |
| `Physics_2021` | 61 | 20 numerical examples of one physical law | `bin/scientificLaws.py` |

Each is a standard HerbBenchmarks module, so the usual entry points work:

```julia
using HerbBenchmarks
import HerbBenchmarks.DreamCoder_2021: List_2021, Tower_2021, LOGO_2021

pairs = get_all_problem_grammar_pairs(List_2021)
p, g  = pairs[1].problem, pairs[1].grammar

interpret = List_2021.make_list_interpreter(g)
interpret(expr2rulenode(:(dc_map(dc_add(1), _arg_1)), g), p.spec)
```

### List processing

217 tasks over lists of integers (`add-k`, `count-k`, `sort`, `is-primes`,
...), 15 examples each. The grammar mirrors `bootstrapTarget_extra()`:
`map`, `filter`, `fold`, `unfold`, `range`, `index`, `length`, `cons`/`car`/
`cdr`, arithmetic and the `is-prime`/`is-square` predicates.

Two tasks (`fibonacci`, `range`) take an integer rather than a list; their
grammars attach `_arg_1` to `Num` instead of `List`.

### Text editing

128 tasks generated by `makeTextTasks()` — which is seeded (`random.seed(9)`)
and so fully determined, and was re-run here to recover the exact task set.
Because identifiers cannot carry punctuation and many tasks differ only in
which delimiter they use, `Text_2021.PROBLEM_NAMES` maps each identifier back
to DreamCoder's own description.

`Text_2021.PROBLEM_CONSTANTS` carries the string constants DreamCoder's
`guessConstantStrings` hands to each task; they appear as extra `Str` rules in
that task's grammar. Without them the "prepend a fixed word" tasks would be
unsolvable — DreamCoder does not expect them to be solved without the literal
either.

### LOGO graphics

160 drawing tasks. A program steers a pen — forward-and-turn, loops, `embed`
(draw, then return to where you were) and pen-up — and must reproduce a target
picture. Angles are measured in **whole turns**, as in the original, so an
n-gon turns by `div_angle(unit_angle, n)` at each corner.

The target is a 28×28 bitmap, DreamCoder's own resolution, and the drawing is
centred but *not* rescaled: a large triangle and a small one are different
tasks.

Every task ships with its reference solution:

```julia
import HerbBenchmarks.DreamCoder_2021: LOGO_2021 as L

prog = L.reference_program("121_5_spiral_snowflake")
L.interpret(prog, L.problem_121_5_spiral_snowflake.spec[1])   # == the target
```

Visualisers: `logo_ascii` prints a picture in a terminal, `logo_ascii_diff`
shows a candidate against a target (`#` both, `+` drawn but shouldn't be, `-`
missing), and `logo_svg` exports the underlying line segments as SVG, which
keeps the smooth arcs the bitmap can only approximate.

```julia
print(L.logo_ascii(L.problem_002_5_gon_1l.spec[1].out))
write("snowflake.svg", L.logo_svg(L.reference_program("121_5_spiral_snowflake")))
```

### Block towers

113 "copy tasks": a program plans how a simulated hand builds a target tower
out of `1x3` and `3x1` blocks, moving left and right along the ground and
dropping blocks. Blocks then settle onto whatever is beneath them
(`simulateWithoutPhysics`) and the tower is centred, so the specification is
the *shape*, independent of where the hand started.

Every task ships with its reference solution, and `tower_ascii` draws one:

```julia
import HerbBenchmarks.DreamCoder_2021: Tower_2021 as T
print(T.tower_ascii(T.problem_064_arch_pyramid_4.spec[1].out))
```

### Physical laws

61 equations and identities from AP and MCAT physics tables — Newton's second
law, Coulomb's law, kinetic energy, parallel resistors, vector algebra —
sampled at 20 numerical points each, with 3-dimensional vectors represented as
lists of reals.

Outputs are floating-point, so **do not compare them with `==`**. DreamCoder
scored this domain with a squared-error loss under a likelihood threshold;
`Physics_2021.solves` is the equivalent here:

```julia
import HerbBenchmarks.DreamCoder_2021: Physics_2021 as P

g = P.grammar_022_work_f_d
P.solves(P.make_physics_interpreter(g),
         expr2rulenode(:(vec_dot(_arg_1, _arg_2)), g),
         P.problem_022_work_f_d)   # true
```

## Deviations from the original DSLs

DreamCoder searches a **typed lambda calculus**: programs can bind variables,
`map` and `fold` take arbitrary synthesised functions, and library learning
introduces recursion. A Herb grammar is context-free over first-order Julia
expressions and cannot bind a variable. Three consequences, each handled
deliberately:

1. **Higher-order arguments become combinators.** `List_2021` derives function
   values from dedicated nonterminals: `dc_add(Num)` *is* the function
   `x -> x + n`, with `n` drawn from the grammar, and `dc_compose` keeps the
   family closed under composition. `map`, `filter` and `fold` stay genuinely
   higher-order rather than collapsing into a fixed menu of specialised
   operators.

2. **Programs that thread state become function values.** In `Tower_2021` and
   `LOGO_2021` every operation denotes a function from state to state, and
   `seq`, `logo_loop`, `tower_loop`, `embed` and `pen_toggle` compose those
   functions. This is what lets a loop run its body more than once without the
   grammar binding a loop index.

3. **Loop indices are unrolled.** DreamCoder's `for i n body` makes `i`
   visible in the body — staircases and pyramids use it, as do the LOGO
   spirals. Those loops are unrolled in the reference solutions. Nothing
   becomes unbuildable, since any finite tower or drawing can be written
   straight-line; the reference programs are just longer here than in the
   original DSL.

Two further additions, both because the missing operation is one DreamCoder
*learns* rather than starts with, and a context-free grammar has no way to
rediscover it:

- `List_2021` provides `dc_append` (and the fold operator `dc_snoc`, which
  gives `reverse`). DreamCoder derives concatenation via recursion during
  library learning.
- `Physics_2021` provides vector algebra — dot product, norm, cross product,
  scaling, `vec_add_many`. The paper's point is precisely that DreamCoder
  *learns* these from `map`/`fold`/`zip` (Fig. 7A); starting from that generic
  basis the tasks would be unreachable here.

Finally, `Text_2021` represents a string as a Julia `String` rather than as a
list of characters rebuilt with `cons`/`car`/`cdr`. The list operations only
ever existed to implement the word- and character-level primitives, which are
provided directly, so no expressiveness is lost.

## Domains not ported

- **Regular expressions** (256 CSV columns) — the specification is a
  *probabilistic* generative model over strings scored by likelihood, not the
  input/output or single-artefact specification `HerbSpecification.Problem`
  expresses.
- **Symbolic regression** (rational functions and polynomials) — the task set
  is regenerated at random on every run of `bin/rational.py`, with no seed, so
  there is no canonical set to port. `Physics_2021` covers the same
  equation-discovery ground with a fixed task set. The domain also relies on
  gradient descent over real-valued parameters inside the search loop.
- **Recursive programming** (20 tasks from a 1959 Lisp basis) — the whole
  point of the domain is synthesising recursion from the Y-combinator, which
  a context-free grammar cannot express.

## Regenerating the data

`data.jl`, `solutions.jl`, `metadata.jl` and `signatures.jl` are generated
from the `ec` checkout rather than written by hand; the generators and
instructions are in `scripts/`. The LOGO targets are generated by running the
reference programs through this module's own renderer, so a target can never
disagree with its own reference program over a floating-point rounding
difference.

You do not need any of this to use the benchmark — the generated files are
committed.
